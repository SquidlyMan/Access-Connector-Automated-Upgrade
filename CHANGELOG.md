# Changelog

Versions are those of `Invoke-AccessConnectorUpgrade.ps1` and `Invoke-ConnectorUpgradeLocal.ps1`, which are released together.

## 1.5.0 - 2026-11-23

- **Fleet file from a spreadsheet** (`-ImportFleet <file>`). Reads an Excel workbook (`.xlsx`, the first sheet that is not hidden) or a CSV file (`.csv`, `.txt`, `.tsv`; encoding and delimiter detected) with one row per connector, checks it, and writes the fleet file. Rows with the same `Group` make one connector group (group names ignore case); a group setting is given on one row and may be left blank on the others. Problems stop the import with nothing written, naming the spreadsheet rows; warnings are shown and the file is written. The usual Excel damage (`26.10` turned into `26.1`, semicolon CSV files, encodings, `="..."` cells, error values such as `#N/A` and `#REF!` in a workbook or written as text in a CSV file) is handled or reported. Columns that look like password columns, and unknown columns, are refused by name. `Services` may hold one service per line (Alt+Enter); a line break in any other cell is a problem. The checks a run makes on a fleet file are made too; missing staging files are warnings here, shown as one note.
- Hidden sheets in front of the first visible one are passed over and named in a note, and the plan says which sheet was read, for example `(xlsx, sheet 'Fleet' of 3)`. The plan shows each group's services, a line with its installer, config, PFX, account, syslog and trust store, its installer settings and its connectors.
- The fleet file is written to `-FleetConfig`, `fleet.<name>.psd1` with `-Fleet`, or `fleet.psd1`, in the layout of `fleet.example.psd1`. The target is turned into a full path (a relative `-FleetConfig` is taken from the current folder); a `-FleetConfig` that names a folder, or a file in a folder that does not exist, stops with nothing written. `-Fleet` given with `-FleetConfig` is named as ignored. An empty `-ImportFleet` value stops at once instead of falling through to a normal run.
- An existing fleet file keeps its top-level settings and is first copied to `<file>.bak-<yyyyMMdd_HHmmss>`, with `-1`, `-2` and so on added when that name is taken, so a copy is never overwritten. One that holds groups is replaced only after `YES` (or `-Yes`); one that holds no groups, such as the file a partial Discover starts, is replaced without asking, because there is nothing in it to lose (the copy is still made). Before that, and in the dry run too, a note names every group of the current file that the spreadsheet does not hold (`removes <n> group(s) the spreadsheet does not hold: ...`) and, for each group that is kept, every setting the current file sets that the spreadsheet leaves blank (`the current fleet file sets ExpectVersionPrefix, which the spreadsheet leaves blank, so the new file will not`); a true/false setting that is false is not named. The new file is written under a temporary name and moved into place, then read back and compared with the spreadsheet; on a difference the previous file is put back. `-DryRun` shows what would be written and writes nothing.
- When neither `-Fleet` nor `-FleetConfig` is given and `fleet.<computer name>.psd1` or `fleet.<domain>.psd1` is beside the script (which a run would pick before `fleet.psd1`), a note says so and the next commands name the file written with `-FleetConfig '<full path>'`.
- The audit log line of an import says `mode=ImportFleet`, with `stage=import` or `stage=import-dryrun`.
- **Discovery of existing connectors** (`-Mode Discover`). Reads each connector's current settings over SSH with one short read-only script on standard input, under Windows PowerShell 5.1 (nothing is copied to or written on the connector, unlike Verify), and writes a draft spreadsheet in the import's columns, with notes on what was found and what is left to fill in. Only allow-listed registry values and `install.properties` lines are kept: each line's name is checked first, and the value of any other line, the client secrets and the PFX password included, is never kept, compared or sent back. The installer, es-config file, PFX and trusted certificates are matched by file name in the staging folder; no es-config file or PFX is opened. Unreachable connectors get a row with the reason, and make the exit code 1.
- Discover's hosts: with `-Connector`, those hosts (no fleet file needed when neither `-Fleet` nor `-FleetConfig` is given), each still matched with its fleet entry whatever group it is in, and `-Tenant` named as ignored; without it, the fleet file in use, limited by `-Tenant`. A fleet file named with `-Fleet` or `-FleetConfig` that does not exist stops the run.
- The es-config file is matched by the tenant's full host name, not as part of a longer name (`dev.tenant1.example.com...` is not `tenant1.example.com`); only when no file has it, by the tenant's first name part as a whole word, and only in a file name that holds no dotted name at all (a dot followed by a letter anywhere but in the `.json` extension, as in `tenant2.example`, rules it out), with the note `ConfigFile matched by the tenant's first name part only (<label>): check it`. Exactly one file must match.
- For a host in the fleet file, `Installer`, `InstallerVersion` (only with the entry's installer), `ConfigFile`, `Pfx` (only with Kerberos Auth) and `TrustStore` (only when the connector trusts extra certificates) that discovery could not fill are taken from its entry and noted (`taken from fleet entry <Name>: <columns>`). An `InstallerVersion` taken from the entry is written with four parts (`26.10` becomes `26.10.0.0`), so Excel keeps it as text. An entry's own `TrustStore` is kept for its hosts; it wins over the generic `TrustedCerts`. `ExpectVersionPrefix` is never filled, because Excel would turn `26.10` into `26.1`.
- Discover's notes: `fill:` lists only the required columns; `set Pfx if a PFX is used: without one the installer makes a self-signed certificate` for a Kerberos Auth row with no PFX; `the connector trusts extra CA certificates: set TrustStore`; `not read on the connector: ...` for read errors, which are also shown on the host's line as `not read: ...`. The `Java4Shell patch flag present` note is left out when the fleet file in use sets `JavaPatchDir`, because the file the next commands import into keeps it (that fleet file after a full read, the new file after a partial one). Settings that differ from the fleet entry only in upper and lower case take the entry's spelling and do not split a group.
- Discover's `Group` names: rows that would share a group but differ in a group setting are split, and the row or rows closest to their fleet entry (fewest columns in the `differs from fleet entry` note) keep the entry's name; the others get `-2`, `-3` and so on. Among rows that are equally close, and for connectors not in the fleet file, the first in the sheet keeps the name. The order of the rows in the sheet is not changed.
- New `-ExportCsv <path>` for `-Mode Discover`: a file, or a folder (one that exists, a path ending in `/` or `\`, or a path with no file extension), which then gets the dated name. Default `fleet.discovered_<yyyyMMdd_HHmmss>.csv` beside the script; a relative path is taken from the current folder. Before any connector is read, the run stops when the file exists (it is never overwritten); a folder that does not exist is made, as for `-AuditLog` and `-ErrorLog`. An empty value stops at once.
- Discover's next commands: after a full read of a fleet file they import into that file, as `-Fleet <name>` when `-Fleet` was used, else by its full path (`-FleetConfig '<full path>'`). A read is partial only when `-Tenant` or `-Connector` left some of the fleet file's connectors out; naming every one of its hosts with `-Connector`, or choosing every group with `-Tenant`, is a full read. After a partial read, Discover itself writes a new fleet file `fleet.discovered_<yyyyMMdd_HHmmss>.psd1` beside the fleet file, holding the original's top-level settings (`StagingRoot`, `StagingFolders`, `CentralLogRoot`, `InstallScript`, `JavaPatchDir`) and no groups, and the next commands import into it (`-FleetConfig '<full path>'`). The warning says how many connectors were left out, names the new file, and says that importing the draft into the original would replace the whole file and drop the groups the draft does not hold. The import carries those top-level settings over, so the Java4Shell patch folder and a custom staging root are kept. With no fleet file the commands carry neither switch. A connector that could not be reached still counts as read: its row says `not reached` and has no `Group`. Deleting that row before the import removes the connector from the fleet file; the import's note names every connector it would remove.
- Switches that have no effect with `-ImportFleet` or `-Mode Discover` are named before anything starts.
- Fixed, in every mode: a run that needs a prompt answered (a password or an account) but has no terminal, because its input is redirected or because it was started with `pwsh -NonInteractive`, now stops at the first prompt with exit code 1, an error-log and an audit entry, and the message `A prompt needs an answer, but this run has no terminal to type it in: <prompt>. Run it from an interactive terminal (passwords are only ever asked at prompts), or use -Mode Stage. Nothing was changed.` The `or use -Mode Stage` part is given only in the SSH and WinRM modes; at the `Type YES` prompt the message says `Add -Yes to confirm without a prompt` instead. A scheduler that gives the run a console without redirecting its input is not detected: start scheduled runs with `pwsh -NonInteractive`. Before, in 1.4.1 too, a run with its input redirected ended silently with exit code 0 at the first password prompt.
- Fixed, in every mode: the plan read `chosen by given with -FleetConfig` when the fleet file was named with `-FleetConfig`. It now reads `chosen by -FleetConfig`.
- Help of the orchestrator: `-FleetConfig` is a path, a relative one taken from the current folder; `-ExportCsv` is a file or folder; OUTPUT gives the exit codes of `-ImportFleet` and `-Mode Discover`; REQUIREMENTS says Discover needs `ssh` only and `-ImportFleet` neither `ssh` nor `scp`; the spreadsheet section says to fill in a copy of a template saved under a name of your own.
- Spreadsheet templates `FleetDeploy/fleet.example.xlsx` (sheets `Fleet`, `Columns`, `Read me`; the rows formatted as Text) and `FleetDeploy/fleet.example.csv`, built by `tools/build_fleet_template.py`. Step 6 of the `Read me` sheet says to save under a name of your own (for example `fleet.xlsx`), not over `fleet.example.xlsx`, which is tracked in the repository.
- Offline tests: `tools/test_fleet_import.ps1` (57 cases), `tools/test_fleet_discover.ps1` (42, including static safety checks of the remote script and a stand-in ssh; its transport cases are skipped on Windows) and `tools/test_fleet_e2e.ps1` (19, the real script in a temporary copy with a stand-in ssh; skipped as a whole on Windows). The suites remove their temporary folders when they finish. `tools/check_scripts.sh` now runs them, checks that the committed templates equal a fresh build, dry-runs `-ImportFleet` on both templates, removes its own temporary folder, and, besides the ternary operator, `&&` and `||` it already caught, also fails on the PowerShell 7-only `??`, `??=`, `?.` and `?[]` in the helper and the wrapper. It finds them by the syntax tree, so they are found inside `"...$(...)..."` strings too; the discovery suite checks the remote script the same way.
- Run 2026-11-23 with the final build (orchestrator SHA-256 beginning `e6f62f331d1b`), read-only, over SSH from a macOS admin machine: `-Mode Discover` read all ten lab connectors (26.10.0.0, two forests, four tenants); its read script ran under Windows PowerShell 5.1 on the connectors from standard input, and nothing was copied to them. Every row of both drafts was complete (`0 need values filled in`). Imported back with `-ImportFleet` into scratch copies of the two hand-written fleet files, every connector had the same settings as those files (installer, installer version, configuration file, PFX, trust folder, services, service account, syslog target, ports, proxy, install folder, FIPS mode), with two exceptions. `ExpectVersionPrefix` was blank, by design, and the import's dry run named it for every group, including the group Discover split off as `<entry>-2` (`the current fleet file sets ExpectVersionPrefix, which the spreadsheet leaves blank`; the split-off group was named after a later change, re-checked offline on the same drafts). One connector's syslog host name had been mistyped on the connector at its original installation, a real difference, noted `differs from fleet entry ...: Syslog`: that connector went to `<entry>-2`, and the other connector of that entry, installed correctly, kept the entry's name. A partial read (`-Tenant` naming one group of a fleet file with two) gave the warning `Only part of <file> was read (2 of its connectors left out)` and a new fleet file with the original's top-level settings (`JavaPatchDir`, `StagingRoot`) and no groups; the import shown ran into it without `-Yes` and wrote the group with those settings kept. Not yet run: `-ImportFleet` on a workbook saved by Microsoft Excel itself; anything on a Windows admin machine; discovery of connectors with a proxy, custom ports, a non-default install folder or FIPS mode; case-only grouping on real connectors; the stop at a prompt with no terminal (end-to-end suite only). ## 1.4.1 - 2026-11-22

- **A dry run always runs the pre-flight checks.** Before, on a connector already on the installer's version, the wrapper decided to skip before its checks and the dry run reported `DryRunPassed` without testing any password. Now the PFX, configuration file and service account checks run every time.
- The dry run says what a real run would do: a connector a real run would skip gets `DryRunPassed` with the note "A real run would SKIP this connector..." on screen, in the summary and in the CSV message; one a real run would refuse (installed version newer than the installer) gets `DryRunFailed` with the reason, after the checks.
- Help text of the orchestrator (`-DryRun`) and the wrapper updated to match.
- Getting Started: the tool's full legal disclaimer at the top and bottom (red in the Word and PDF guides, a Caution box on GitHub); why SSH key sign-in is used and how it is secured and made seamless; what is not available over WinRM without SSH; connector servers need only Windows PowerShell 5.1.

## 1.4.0 - 2026-11-22

- **Installer settings through the fleet file** (issue 2): `InstallDir`, `EnableFips`, `DirectorySyncPort`, `UserAuthPort`, `KerberosAuthPort`, `VirtualAppPort`, `ProxyHost`, `ProxyPort`, `ProxyUser` and `NonProxyHosts` per fleet entry, passed to the wrapper through `job.json`. When `ProxyUser` is set the proxy password is asked at run time with the others and handed over like them (standard input, WinRM parameter, protected task file, `-Prompt`, `-Schedule`).
- The settings are checked before any connector is contacted (port numbers, duplicate ports, a full Windows path for `InstallDir`, proxy settings without `ProxyHost`, spaces or quotes) and shown in the plan. An unknown setting in a fleet entry is named in a note, so a misspelling is not dropped silently.
- The helper refuses (`Blocked`) a job whose FIPS setting differs from the installed connector's, because FIPS mode cannot be changed after install. It warns when `InstallDir` names a different folder than the one the connector is in.
- The helper finds a connector installed outside `C:\Program Files` from the installer record, the job or the service paths.
- The helper reads four secret lines on standard input instead of three (configuration, PFX, service account, proxy). Both scripts are released together, and the orchestrator copies the helper on every run.
- `Install-AccessConnector.ps1`: the served-certificate check now reads the certificate with a TLS handshake of its own, so it works under Windows PowerShell 5.1 (before, it silently never compared). After an upgrade a mismatch is a warning, because the vendor installer never carries the PFX through an upgrade; after a fresh install it is an error.
- `Install-AccessConnector.ps1`: the keytab-log check judges only what `setupKerberos.ps1` added to `krb5-setup.log` during this run, and the newest `RESULT` line (before, it read the first `RESULT` line of the whole log and any old `Password set failed`). It also turns on TLS 1.2 for its health checks, refuses a proxy password containing a double quote, and drops a trailing backslash from `-InstallDir`.
- The orchestrator checks for PowerShell 7 before anything else, `-Help` included, and says how to start it with `pwsh`.
- MIT licence (`LICENSE`); the help's ABOUT section says so.

## 1.3.1 - 2026-11-22

Help text only. No change to what the scripts do.

- Help, examples and comments no longer name a connector version, a lab or lab tenants. Examples use `TENANT1`, `TENANT2`, `connector.example.local` and `~/.ssh/connector_ed25519`.
- Synopsis now says the version installed is that of the installer named in the fleet file, and that the Java4Shell patch runs only when the fleet file names its folder.
- `Install-AccessConnector.ps1`: two example lines changed to example names.
- New generic `fleet.example.psd1` for the current fleet-file layout.
- First release in this repository, with full documentation.
- Documentation: how to choose services for a single connector or a group of connectors (one fleet entry per connector group).

## 1.3.0 - 2026-11-22

- New `-Mode RepairCertificate` (helper: `-RepairCertificate -CertFile -Reapply`): puts the PFX certificate on the Kerberos Auth service with the vendor maintenance script, after copying the service configuration, and puts the copy back if the result is not right. Asks for the PFX password only.
- Upgrades of Kerberos Auth connectors now end by checking the certificate served and putting the PFX certificate back. The vendor installer does not carry it through an upgrade.
- `-Mode Verify` shows the certificate served and marks a self-signed, misnamed, expired or unreadable one.
- The final health check fails if the Kerberos Auth service serves anything other than the PFX certificate.
- Interrupted certificate changes are detected through a marker file.

## 1.2.3 - 2026-11-22

Screen output and messages only.

- Lines wrapped to 78 columns with hanging indents; blank lines around framed blocks; dates dropped from relayed timestamps.
- Summary grouped by tenant; state shown as `services 4/4 up`.
- "Files missing" error names another copy of the staging folder that has the files, with the `cd` command. Needs `StagingFolders` in the fleet file.
- The temporary `job.json` is written in a folder of its own, so two sessions staging at once cannot collide.

## 1.2.2 - 2026-11-22

- The vendor installer's MSI log is cleaned of recorded passwords after every install, on the connector and in copies brought back.
- After a failed install, services that were running before are started again and, when the Kerberos set-up did not run, the keytab copy is put back.
- The helper refuses to start when the server's PowerShell module-logging policy would record passwords.
- SSH's own error messages are shown in red.

## 1.2.1 - 2026-11-21

- `RepairKeytab` skips connectors whose keytab already holds keys, judges success by the vendor exit code and log rather than size alone, and always works one connector at a time.
- A failed dry run stops that tenant's other connectors.
- The staging folder on the connector is locked to Administrators and SYSTEM when created.

## 1.2.0 - 2026-11-21

- Kerberos Auth connectors: the upgrade runs on the connector as a one-time scheduled task under a domain admin account, so the keytab can be rebuilt without anyone signing in to the server. The task removes itself.
- New `-Mode RepairKeytab`.
- New `-RunAsCredential` and `-SkipDomainCheck`.
- `Install-AccessConnector.ps1`: a keytab under 32 bytes counts as not present.
