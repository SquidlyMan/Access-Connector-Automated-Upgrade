## 1.5.2 - 2026-11-24

Fixes for the faults the first runs of 1.5.1 found on 2026-11-24, and `-Schedule` over SSH. Every new path is built and tested offline, not yet proven on a server (Validation Record).

- **The SSH hint's test command can be copied as shown (#5).** The hint after `Permission denied` now ends with `Test by hand: <command>` and nothing after it. 1.5.1 ended it with the sentence's full stop (`... hostname.`), so a copied command ran `hostname.` on the server. No other hint ends with a command.
- **The SSH hint names the account as well as the key (#6).** SSH gives the same `Permission denied` for an account that does not exist on the connector and for a key it does not accept, and the hint used to blame only the key. It now reads `the connector refused the sign-in for <user>: the account does not exist there, or its key was not accepted; SSH does not say which. Check the account name (SshUser in the fleet file, or -SshUser) and that its key is authorised on the connector (Getting Started 4.4); name the key with -SshKey <file>, or with an IdentityFile line for these hosts in the SSH settings file (Getting Started 4.7). An 'Invalid user' line in the connector's OpenSSH/Operational event log means the account does not exist. Test by hand: ssh <user>@<host> hostname`. With `-SshKey` the middle part names that key's public key, and the command is `ssh -i <key> <user>@<host> hostname`.
- **`Install-OpenSSHServer.ps1` 1.0.1: no `Set Alias` lines under `-WhatIf` (#7).** The modules the script uses (CimCmdlets, Microsoft.PowerShell.Security, NetSecurity, NetTCPIP, ScheduledTasks, Dism, and ServerManager where it is there, for `Get-WindowsFeature`) are loaded at the start with `-WhatIf` and `-Confirm` off for the load only, so loading them no longer prints `What if: Performing the operation "Set Alias" ...` lines before the first step. Every change still honours `-WhatIf` and `-Confirm`. The login-alert trigger object, built in memory only, no longer asks a second question under `-Confirm`.
- **`Install-OpenSSHServer.ps1` 1.0.1: on a first install, TCP 22 is limited before sshd first starts (#8).** With `-AllowFrom`, the rule `OpenSSH-Server-In-TCP` that the install adds (TCP 22 from any address) is limited to `-AllowFrom` right after the install, before sshd first starts. A rule that cannot be limited is disabled until the firewall step, which tries again; one that can be neither limited nor disabled stops the run before sshd starts. Without `-AllowFrom` the rule stays open to any address as before, and the run now warns. sshd still first starts with the Windows default `sshd_config` (password sign-in on until the `sshd_config` step), because sshd makes that file on its first start.
- **`Install-PowerShell7.ps1` help names GitHub's digest (#9).** The help now says that, for a release found through the GitHub releases API whose `hashes.sha256` cannot be read or does not list the MSI, the SHA-256 is checked against the digest GitHub records for the file, and that with neither nothing is downloaded or installed. The code already did this.
- **Getting Started: "Tested" lines brought up to date (#10)** with the runs of 2026-11-24 in the Validation Record.
- **`-Schedule` works over SSH with key sign-in (#11).** The helper's `-Prompt -Schedule` now writes `secrets.dat` with machine-scope data protection, as the run-as task does, instead of the signed-in user's (`ConvertFrom-SecureString`), which a session signed in by key cannot use: 1.5.1 stopped there with `Could not register the scheduled task: Access is denied.` `secrets.dat` is created empty, limited to Administrators and SYSTEM (inheritance removed), then written; the job deletes it when it reads it, and it is removed again if a later step fails. A `secrets.dat` written by 1.5.1 is still read. The error now names the step: `Not scheduled: <why>. Nothing was written.` (a time that has passed, a task running, an account refused, no password), `Could not protect the passwords for the scheduled task (machine-scope data protection): ...`, `Could not write the secrets file <path>: ...` or `Could not register the scheduled task as <account>: ...`, each followed by `secrets.dat was removed and no task was registered.` once the file had been written. A `secrets.dat` left by an earlier `-Schedule`, whose task may still be pending, is moved aside rather than overwritten, put back when a step fails, so that the earlier task still runs as booked, and deleted only once the new task has replaced it. The audit line on failure has `step=check|protect|write|register`; on success it adds `account=<account>`.
- **`-Schedule` asks for the account the job runs as (#12).** `Account the scheduled job runs as (DOMAIN\user); Enter for <signed-in account>`, or `-RunAsUser` (with `-RunAsPassword`, or the password is asked). The task runs under that account with highest privileges, so it must be an administrator of the server. A job with the Kerberos Auth service needs a domain account: a local one (no domain part, a `user@domain` name included, `.\user`, `\user`, `<this computer>\user`, `NT AUTHORITY\` or `BUILTIN\`) is refused before its password is asked or anything is written, with `give the account as DOMAIN\user`. The signed-in account is offered at Enter only when it would pass that check; over SSH it is usually the server's local administrator, so for Kerberos Auth nothing is offered. Built-in service accounts (SYSTEM, LocalSystem, Local Service, Network Service) are always refused. Before the password prompt the helper says `The job will run as <account>. Task Scheduler keeps the Windows password of <account> until the task deletes itself: when the run ends, or at <time + 12 h> if it has not run by then.` `-Schedule` with `-RunAsUser` is no longer refused; with `-RunAsTask` it still is: `-Schedule cannot be used with -RunAsTask: -RunAsTask starts the work now. To schedule the job under another account, use -Prompt -Schedule, and give the account at its prompt or with -RunAsUser.` The earlier checks (a time that has passed, a running `AccessConnectorUpgrade` task, both again after the password prompt, nothing written before them) are unchanged. `-SkipDomainCheck` does not relax the domain-account rule. The orchestrator's `-Mode Stage` next steps say that the scheduling command asks for the account (a domain admin for Kerberos Auth) and works over `ssh -t`.
- **`Install-PowerShell7.ps1` and `.cmd` 1.0.1: the release lookup under Windows PowerShell 5.1, and the launcher waits on failure (#13).** The lookup through the GitHub releases API, used when the current stable release has no MSI for the processor (seen with v7.7.0), no longer stops with `The release lookup failed: Argument types do not match` under Windows PowerShell 5.1: it hands the release choice a plain array, and the choice no longer wraps a list in `@()`. `Install-PowerShell7.cmd` now waits for a key when the script does not succeed (an exit code other than 0, 3010 or 1641, or the script could not be started), double-clicked or run from a console; after 0 it ends at once (1.0.0 always waited after a double-click). After 3010 or 1641 (installed, a restart is needed) it says to restart Windows and waits for a key when it was started without arguments (double-clicked), so that the notice is seen. It never waits as SYSTEM, or with the new `-NoPause` (found by its first four characters, so `-NoPa` and `-NoPause:$true` count too), which it passes on to the script (the script accepts it and does nothing with it); `-No` alone is now ambiguous (1.0.0 took it for `-NoMicrosoftUpdate`). It passes the exit code back on every path. A leading empty argument (`""`) now counts as an argument and is refused by the script; 1.0.0 took it for a double-click and an install. The `.cmd` now carries a version line.
- **WinRM: `0x8009030E` counts as a refused sign-in (#14).** `A specified logon session does not exist` (SEC_E_NO_CREDENTIALS), which Negotiate gave for an account that does not exist, now stops the tenant (and the run, unless `-ContinueOtherTenants`) at the first connector, in dry runs too, instead of trying every connector with the same credential. It is matched by the transport error code `-2146893042` (or `2148074254`, the same bits unsigned), by an exception's HResult, and by the words `logon session does not exist` or `0x8009030e`. The general ending of Negotiate errors, `credentials are not valid on the target server, or if the server identity could not be verified`, is deliberately not matched, because server-identity faults (such as `0x80090322`) end the same way.

It now says which it was: `cannot reach <host> over SSH: <SSH's own reason>`, or `signed in to <host> over SSH, but could not create <folder>: <the error on the connector>`; the folder step answers `ok` only when its folders are really there. When the step (or the sign-in check below) did answer but ssh still failed afterwards, because the session dropped (or, for the sign-in check, which has a 120-second limit, did not end in time), it is not called a failure to connect: `signed in to <host> over SSH and the step answered, but ssh then ended with exit code <n>: <reason>`, or, from the sign-in check, `... but the session did not end within 120 seconds`. Every report of an SSH connection failure (that step, the new check below, and Discover's `not reached`) ends, when SSH's reason is one of these, with a short hint: `Permission denied` (the key was not accepted: name it with `-SshKey`, or add an `IdentityFile` line, Getting Started 4.7, and test with `ssh <user>@<host> hostname`, the account in single quotes when it holds a backslash, as a domain account does, so that zsh and bash keep it), `Host key verification failed` or `REMOTE HOST IDENTIFICATION HAS CHANGED` (`ssh-keygen -R <host>`, Getting Started 4.6), `Could not resolve hostname`, a connection that times out, is refused or has no route (the port is not reachable: firewall, or OpenSSH Server not running), and `Too many authentication failures` (name the key, or set `IdentitiesOnly`). The run-as task and `-Schedule` now build that action with one function. Built, not yet run (it needs a Windows connector).

## 1.5.0 - 2026-11-23

- **Fleet file from a spreadsheet** (`-ImportFleet <file>`). Reads an Excel workbook (`.xlsx`, the first sheet that is not hidden) or a CSV file (`.csv`, `.txt`, `.tsv`; encoding and delimiter detected) with one row per connector, checks it, and writes the fleet file. Rows with the same `Group` make one connector group (group names ignore case); a group setting is given on one row and may be left blank on the others. Problems stop the import with nothing written, naming the spreadsheet rows; warnings are shown and the file is written. The usual Excel damage (`26.10` turned into `26.1`, semicolon CSV files, encodings, `="..."` cells, error values such as `#N/A` and `#REF!` in a workbook or written as text in a CSV file) is handled or reported. Columns that look like password columns, and unknown columns, are refused by name. `Services` may hold one service per line (Alt+Enter); a line break in any other cell is a problem. The checks a run makes on a fleet file are made too; missing staging files are warnings here, shown as one note.
- Hidden sheets in front of the first visible one are passed over and named in a note, and the plan says which sheet was read, for example `(xlsx, sheet 'Fleet' of 3)`. The plan shows each group's services, a line with its installer, config, PFX, account, syslog and trust store, its installer settings and its connectors.
- The fleet file is written to `-FleetConfig`, `fleet.<name>.psd1` with `-Fleet`, or `fleet.psd1`, in the layout of `fleet.example.psd1`. The target is turned into a full path (a relative `-FleetConfig` is taken from the current folder); a `-FleetConfig` that names a folder, or a file in a folder that does not exist, stops with nothing written. `-Fleet` given with `-FleetConfig` is named as ignored. An empty `-ImportFleet` value stops at once instead of falling through to a normal run.
- An existing fleet file keeps its top-level settings and is first copied to `<file>.bak-<yyyyMMdd_HHmmss>`, with `-1`, `-2` and so on added when that name is taken, so a copy is never overwritten. One that holds groups is replaced only after `YES` (or `-Yes`); one that holds no groups, such as the file a partial Discover starts, is replaced without asking, because there is nothing in it to lose (the copy is still made). Before that, and in the dry run too, a note names every group of the current file that the spreadsheet does not hold (`removes <n> group(s) the spreadsheet does not hold: ...`) and, for each group that is kept, every setting the current file sets that the spreadsheet leaves blank (`the current fleet file sets ExpectVersionPrefix, which the spreadsheet leaves blank, so the new file will not`); a true/false setting that is false is not named. The new file is written under a temporary name and moved into place, then read back and compared with the spreadsheet; on a difference the previous file is put back. `-DryRun` shows what would be written and writes nothing.
- When neither `-Fleet` nor `-FleetConfig` is given and `fleet.<computer name>.psd1` or `fleet.<domain>.psd1` is beside the script (which a run would pick before `fleet.psd1`), a note says so and the next commands name the file written with `-FleetConfig '<full path>'`.
- The audit log line of an import says `mode=ImportFleet`, with `stage=import` or `stage=import-dryrun`.
- **Discovery of existing connectors** (`-Mode Discover`). Reads each connector's current settings over SSH with one short read-only script on standard input, under Windows PowerShell 5.1 (nothing is copied to or written on the connector, unlike Verify), and writes a draft spreadsheet in the import's columns, with notes on what was found and what is left to fill in. Only allow-listed registry values and `install.properties` lines are kept: each line's name is checked first, and the value of any other line, the client secrets and the PFX password included, is never kept, compared or sent back. The installer, es-config file, PFX and trusted certificates are matched by file name in the staging folder; no es-config file or PFX is opened. Unreachable connectors get a row with the reason, and make the exit code 1.
- Discover's hosts: with `-Connector`, those hosts (no fleet file needed when neither `-Fleet` nor `-FleetConfig` is given), each still matched with its fleet entry whatever group it is in, and `-Tenant` named as ignored; without it, the fleet file in use, limited by `-Tenant`. A fleet file named with `-Fleet` or `-FleetConfig` that does not exist stops the run.
- The es-config file is matched by the tenant's full host name, not as part of a longer name (`dev.tenant1.example.com...` is not `tenant1.example.com`); only when no file has it, by the tenant's first name part as a whole word, and only in a file name that holds no dotted name at all (a dot followed by a letter anywhere but in the `.json` extension, as in `tenant2.example`, rules it out), with the note `ConfigFile matched by the tenant's first name part only (<label>): check it`. Exactly one file must match.
- For a host in the fleet file, `Installer`, `InstallerVersion` (only with the entry's installer), `ConfigFile`, `Pfx` (only with Kerberos Auth) and `TrustStore` (only when the connector trusts extra certificates) that discovery could not fill are taken from its entry and noted (`taken from fleet entry <Name>: <columns>`). An `InstallerVersion` taken from the entry is written with four parts (`26.10` becomes `26.10.0.0`), so Excel keeps it as text. An entry's own `TrustStore` is kept for its hosts; it wins over the generic `TrustedCerts`. `ExpectVersionPrefix` is never filled, because Excel would turn `26.10` into `26.1`.

The `Java4Shell patch flag present` note is left out when the fleet file in use sets `JavaPatchDir`, because the file the next commands import into keeps it (that fleet file after a full read, the new file after a partial one). Settings that differ from the fleet entry only in upper and lower case take the entry's spelling and do not split a group.
- Discover's `Group` names: rows that would share a group but differ in a group setting are split, and the row or rows closest to their fleet entry (fewest columns in the `differs from fleet entry` note) keep the entry's name; the others get `-2`, `-3` and so on. Among rows that are equally close, and for connectors not in the fleet file, the first in the sheet keeps the name. The order of the rows in the sheet is not changed.
- New `-ExportCsv <path>` for `-Mode Discover`: a file, or a folder (one that exists, a path ending in `/` or `\`, or a path with no file extension), which then gets the dated name. Default `fleet.discovered_<yyyyMMdd_HHmmss>.csv` beside the script; a relative path is taken from the current folder. Before any connector is read, the run stops when the file exists (it is never overwritten); a folder that does not exist is made, as for `-AuditLog` and `-ErrorLog`. An empty value stops at once.
- Discover's next commands: after a full read of a fleet file they import into that file, as `-Fleet <name>` when `-Fleet` was used, else by its full path (`-FleetConfig '<full path>'`). A read is partial only when `-Tenant` or `-Connector` left some of the fleet file's connectors out; naming every one of its hosts with `-Connector`, or choosing every group with `-Tenant`, is a full read. After a partial read, Discover itself writes a new fleet file `fleet.discovered_<yyyyMMdd_HHmmss>.psd1` beside the fleet file, holding the original's top-level settings (`StagingRoot`, `StagingFolders`, `CentralLogRoot`, `InstallScript`, `JavaPatchDir`) and no groups, and the next commands import into it (`-FleetConfig '<full path>'`). The warning says how many connectors were left out, names the new file, and says that importing the draft into the original would replace the whole file and drop the groups the draft does not hold. The import carries those top-level settings over, so the Java4Shell patch folder and a custom staging root are kept. With no fleet file the commands carry neither switch. A connector that could not be reached still counts as read: its row says `not reached` and has no `Group`. Deleting that row before the import removes the connector from the fleet file; the import's note names every connector it would remove.
- Switches that have no effect with `-ImportFleet` or `-Mode Discover` are named before anything starts.

Nothing was changed.` The `or use -Mode Stage` part is given only in the SSH and WinRM modes; at the `Type YES` prompt the message says `Add -Yes to confirm without a prompt` instead. A scheduler that gives the run a console without redirecting its input is not detected: start scheduled runs with `pwsh -NonInteractive`. Before, in 1.4.1 too, a run with its input redirected ended silently with exit code 0 at the first password prompt.
